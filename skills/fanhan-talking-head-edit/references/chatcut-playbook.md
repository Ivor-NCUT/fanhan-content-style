# ChatCut 全流程与排错

这些是 2026 年 10 月 Hosted ChatCut 的实践经验，不保证未来版本仍有相同缺陷。当前 schema、工具返回和实际状态优先；本文不是插件源码或固定 SDK。

## 连接、导入与实时状态

先读当前基础 Skill，通过官方 MCP 新建/定位项目并展示编辑器。Hosted 使用 Codex iab；不操作隐藏数据库、猜端点或个人浏览器。导入按当前 asset-import，先查素材库是否已有同一文件。其他机器路径仅替换主目录前缀并核验。

认证失败核对项目 ID、账号与访问权限；需要人工登录时保留官方登录页。平台拒绝上传不能换工具绕过。转码失败按结构化错误的 retry 方案恢复，先回读素材状态，不反复上传。同样，文件已登记不代表字节和转写已就绪。

长任务保存检查点，可启动本任务专用防休眠进程并记录 PID。只读查看网络路由，不自动换代理。结束仅停本任务进程，不清理其他任务文件。

## 语义剪辑与刷新

加载当前 talking-head-guide。通常通过 read_script → 阅读当前 timeline.md → 语义编辑 → 校验 → apply_script。ASR 一行不是一句；先跨行理解。不在 Script 中直接改写原始词来纠正转写，使用当前转写订正能力后重读。

clean_script 会立即写入，仅用于适合机械处理的固定填充和停顿；操作后重新读取当前文本。预览验证通过且已授权实际剪辑则继续应用，不反复确认；用户只要预览则不应用。

当前 Script 曾使用 `[silence=Xs→Ys]` 表示压缩，箭头为 Unicode；只在当次仍支持时用。删除填充词后两侧静音相加，需计算总保留时长。

结构稳定后再做官方支持的音频接缝平滑；重排可能丢过渡，需要复核。字幕启用时，一批语音修改完成后按提示 refresh 一次，再做自定义字幕；不要每剪一个词就刷新，也别在定制后无故刷新覆盖结果。

## 变速与原声

读取当前速度和所有可听音轨。用当前官方支持的保音高变速；speed=1.1 不等于声音不变调。比较源音与输出的听感和音高，核查保音高设置。

历史工程使用过单独保音高人声音轨覆盖全片，并静音视频嵌入声；关键经验是避免双声、同步长度与切口，不是强制所有新工程拆音轨。当前 Hosted 若不允许本地音频编辑，不照搬历史本地变速方案；原生能力不足则说明具体限制，保留工程，使用当次授权且官方支持的恢复路径。

单独声轨存在时，裁剪和速度变化必须同步声音、视频与字幕。不能用改采样率假装保音高，也不能本地压平整段 MP4 代替 ChatCut 可编辑项目。

## 多版本、复制和 revision

用当前 manage_timelines 创建独立版本，记录新 ID。复制后回读视频、原声、标题、字幕来源和翻译覆盖，不能假定深复制保全一切。

工作目标和 UI 显示的时间线可能不同。字幕写入前确认两者及 captions program 均对应本次版本。历史批处理中切换工作时间线曾导致“没有字幕 program”：重新定位目标、读取最新 revision，从尚未成功的操作继续，不从头重放。

字幕写入串行，每步使用新 revision。stale revision、失效卡片 ID 或超时后，先回读哪些已生效，再计算剩余变更。读取所有分页，首 100 张不能代表全片。

## 字幕复制与双语可见性

### ChatCut 0.6.7：双语字幕独立编辑

2026-10-10 的更新邮件说明，原文和译文现在可以分别编辑，双语字幕也支持网页版。当前 Hosted MCP manifest 同样提供独立的原文/译文 Caption Cards，以及按 Card ID 和 revision 调用 `edit_captions` 的 `set_card_text` / `set_card_tokens`。ChatCut 的[字幕文档](https://chatcut.io/docs/transcript-and-captions)也说明 Web Content 面板支持卡片编辑，翻译来源可分别显示、设样式和导出。这适用于已存在的双语字幕。当前 `manage_timelines` 的 duplicate 契约说明会复制 captions（含逐词编辑），这可能缓解复制遗漏；但没有明确保证各语言的翻译覆盖率。以上能力都不证明旧的预览渲染缺陷已修复。

只改一个语言的字幕文字时，先用 `read_captions` 确认目标语言、Card ID、原文、译文、时间范围和 revision，再只编辑目标 Card。单纯改错字或措辞不重建另一语言，也不重复调用 `translate`、`bilingual` 或 `refresh`。若口播转写或句意确实改变，仍需核对另一语言是否语义准确；分开编辑不代表自动同步译文。

写入后重新读取两种语言，确认未编辑语言的文字、时间范围及覆盖率保持不变，再用 `preview_timeline` 检查对应画面。若读回结果有变化，先按最新 revision 回读，只恢复实际受影响的内容；不要重置整套字幕。若无法从当前 schema 明确识别语言或 Card ID，不猜 ID，改用当前已选 ChatCut 表面支持的编辑入口，并按同一标准验收。

0.6.7 的调色轮、Film Look、共享 LUT 和智能主体抠图属于 Desktop；GPT-6.1 Sol 与 ChatGPT 额度说明针对连接 Codex CLI 的 Desktop。本轮核验的工具表只有 Hosted ChatCut MCP，没有 Desktop MCP 工具，因此这些功能不纳入 Hosted 操作步骤。其他会话按实际工具表确认；新增能力不改变本 Skill 已确认的剪辑风格、静态字幕样式或三项交付。

正式纳入日常流程前，在已授权的测试副本上验收：

1. 保存原文与译文的 Card ID、文字、时间范围、revision 和覆盖率。
2. 分别只改一张中文卡和一张英文卡；每次都确认另一语言的文字、时间范围和卡片覆盖率不变。
3. 复制时间线后重新读取所有分页，确认译文覆盖完整；检查代表画面中两种语言都可见，原字幕样式与顶部标题保持不变。
4. 检查最终双语 SRT 的文字、顺序、时间和无标点规范；同时确认无字幕 MP4、双语 SRT、飞书记录这三项交付仍按原要求完成。

测试未通过或尚未执行时，继续使用下面的复制缺译和预览缺字恢复流程，不宣称该缺陷已修复。没有真实素材或获准编辑的项目时，只记录测试步骤，不声称完成了视频实测。

### 复制后英文丢失

历史复制保留中文卡片却漏掉底层英文翻译块。通过增量翻译建立缺失覆盖，再按保存的双语基准恢复已校对英文解决。

今后先比数量、起止帧、文字和覆盖率，只恢复缺项；按最终时间和内容对应新卡片，不能套旧 ID。“翻译成功”也不代表恢复原有校对措辞。

### 数据有英文，预览没有

把中文两行改回一行后，read_captions 曾仍返回英文，但实际画面不显示。有效修复是在受影响卡片明确设置英文 source 的单行 layout，再重写**相同英文文本**，随后预览。

1080×1920 历史恢复位置曾用 left=66、top=1353、width=948，仅为定位参考。按当次画幅与已确认布局换算，不跨画幅硬套。revision 未变不证明渲染未变；每类修复先试一张，再仅批量修受影响卡片并全检。

### 旧换行和逐卡覆盖残留

单行恢复同时检查卡片总 layout、各语言 layout、显式换行、逐卡样式。改全局 maxLines 不一定覆盖逐卡配置；删换行后旧字符范围样式可能仍在。

先保存校对文字和时间，再按当前 schema 清冲突覆盖并重设单行文本，检查另一语言。不要整卡 reset 丢掉文字。写入成功不是视觉验收。

### 关闭继承效果的兼容错误

历史 source_update 顶层 presentation 被拒绝时，兼容写法 `style: {highlightUnit: "off"}` 曾成功并回读成 canonical presentation。仅当当次 schema 支持才用，不反复试旧 payload。

给 activeStyle.animation 写 null 或空对象曾被拒绝。不要靠试空值清效果，优先明确的关闭开关；必要时在新静态 source 恢复已保存文字和时间。通过连续预览帧和导出确认。这里只说明移除继承效果，不提供动画制作方法。

## 导出与声音验证

- SRT 导出曾拿到原始 ASR 而非最终语义卡片。核对数量、内容和时间，不一致则从最终卡片基准生成文件，不能交付未经核对的 ASR。
- submit_export 后记录 renderId，用 track_export 查询；不是生成工具的 progress。按 checkBackAfterSeconds 等待，排队/渲染中都不算完成。
- complete 且有 downloadUrl 后检查本次新下载。旧的 crdownload 不是本次下载证据，要看文件名、开始时间和增长；没有本次自动下载时下载返回地址到唯一文件名，核对大小并打开。
- 不猜存储路径或套其他 render 的地址。下载完成后探测流、时长、分辨率，完整解码并抽查实际输出帧。
- 仅文字层不同的两版音轨应一致；不同先查静音/音量和原声选择。
- AAC 有编码延迟/填充。未对齐的逐样本相关可能很低；历史估计偏移约 43 ms 后对应正常。估计本次偏移，不能固定套 43 ms。相近时长、音高抽样或相关系数都不能单独替代实际听审与唇音同步检查。

成功写入不等于画面可见，字体属性正确不等于字体渲染正确，音轨相同不等于剪辑正确。分别验证对应结果。
