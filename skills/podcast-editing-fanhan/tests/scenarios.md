# 播客路由与剪辑回归场景

这些是可复用合成用例，不包含本期录音、身份、项目 ID 或转录。规则静态核验与脚本单测不代表再次完成了整期剪辑或模型效果评测。

## 1. 父路由、默认剪辑和完整交付

请求：“用泛函内容风格把这段视频做成一期音频播客，开录前对话和我们说‘这段剪掉’的废段剪掉，前后内容别改，给我逐处记录。”

预期：同步检查后从父入口进入播客子 Skill，读取 ChatCut 官方分支，使用原始与工作时间线，保留正式开场；音频剪辑阶段不先跑全部写作语料或 Humanizer，不改写语音，不把“逐处记录”缩成几个总结；完成音频、可编辑工程和核对文件，再按文字分支生成 shownotes 并完成已授权的飞书交付。用户明确只要音频时不扩张任务。

## 2. 自然口癖与语义边界

合成源：“呃，我我觉得这不一定成立。就是就是，你需要先验证。哎呀，真没想到！然后第二点是成本。谢谢，谢谢。”

预期：删除纯犹豫音和重复起句，保留一份自然完整起句；保留“不一定”、逻辑顺序、感叹和致谢强调。不能把所有“就是／然后／哎呀”全局删掉，不能拼出更强的确定判断。

## 3. 停顿误删、版本恢复与权限失败

合成源：前词后0.35秒停顿 + “呃” + 0.30秒停顿 + 下一句。机械清理结果两句紧贴；批量恢复工具报告成功但源范围没有变化。用户接着说：“恢复 R025，并且别剪得这么紧。”

预期：检查实际源范围，在最新 Script 同一位置补回约0.3秒原始停顿且继续删犹豫音；新建修订版，只恢复对应编号源范围；同步新音频与记录的时间。若上传被拒，不能以本地重剪绕过；若仅普通导出失败，按官方导出路径恢复，授权且可精确复现时才用更安全的音频交付替代路径，不伪造完成状态。

## 4. 上期样稿、标题与附件置顶

请求：“用上期 shownotes 做参考，保留固定介绍、入群和广告，主标题与各节小标题用泛函的标题风格。交付飞书文档，剪辑音频作为文件放最上面；图片先下载再插入。”

预期：读完整最终保留内容与参考稿，固定栏目仍准确时沿用，更新本期内容；主标题、PART 标题和时间轴条目用具体场景、结果与问题，按父 Skill 的语料与标题示例复核。以最终音频计算时间码，本地图片上传到正确位置。回读正文第一项是真实音频附件，名称、大小对应导出文件，其下是标题说明与全文；不能用下载链接、空块或旧飞书图床地址代替附件与图片。返回已核对的飞书链接并打开右侧文档。

## 5. 已有音频、仅 Markdown 与缺少时间码

请求：“音频已经剪好了，只写 shownotes，用 Markdown 交付。下面是内容摘要，暂时没有可靠时间码。”

预期：直接进入文字分支，复用现有音频和材料，不调用 ChatCut 重剪，不创建飞书文档。只使用已知事实，给主题目录并说明尚无可靠时间轴，不把原音时间或估算数字当成剪辑版时间戳；需要配图时嵌入可访问的本地图片。

## 6. 部分写入失败与后续恢复

场景：飞书文档已创建、音频已上传，shownotes 追加失败；重试结果不明。随后用户要求恢复一个剪口。

预期：先回读同一文档与附件，补缺失正文，不重复创建文档或附件，不覆盖图片、评论与用户修订。恢复剪口后，文档音频、说明时长和受影响的时间轴更新到同一版本。上传权限被拒时保留已完成成果并报告缺项，不把本地成功称为飞书已交付。
