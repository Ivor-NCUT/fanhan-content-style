# ChatCut 调用约定

本文件封装调用顺序与保护条件，配合当前官方插件 Skill 和 MCP schema 使用。下列示例来自已使用过的 hosted 合约；升级后先核对参数，不把示例当作固定版本 SDK。不要复制官方插件源码或私有录音到 Skill 仓。

## 项目、素材和版本

已有项目用其编辑器 URL／用户指定对象识别 projectId；新的录音任务按官方规则创建项目。查看当前项目与素材库，复用正确且就绪的源，不根据历史名字猜项目。导入本机素材走 `asset-import` 的正式路径；保持上传授权和官方认证流程。

`manage_timelines(action:"duplicate", timelineId:原版, name:版本名称)` 可保留原版。后续含 `timelineId` 的调用显式指定目标；Script 与 `smooth_audio` 一类依赖工作目标的工具要先确认工作时间线，不能把浏览器中看到的标签当作默认目标。实际轨道从 `preview_timeline` 取得，只有确实存在音频轨才用 A1。

转录状态用 `browse_assets` 与 `track_progress(target:"transcription")`，空闲／明确错误才按当前说明触发或恢复。不因一次等待判死；不重传已就绪素材。对源录音查词和时间用 `inspect_asset`／`find_transcript`；决定保留或删除的话语用 Script。

## Script 循环

1. `read_script({projectId, showSilence:true, track:已核实轨道})`；保存基线和修改意图。外部合约返回 inline `timelineMd` 时在本机编辑完整字符串再传回；有受支持的工作区时编辑其实际文件。
2. 用同一行的 `~~...~~` 删除源字词，保留未删除原话；不要通过重新输入“顺口版本”跳过中间词。保留头部 stamp、源标题、轨道和已有 `[sN@M]` 实例标识。中文不添原文没有的空格。转录误识走 `manage_transcript` 的修正操作，不靠 Script 改写。
3. 局部停顿用 `[silence=0.9s→0.5s]`，箭头为 Unicode `→`；单改成 `[silence=0.5s]` 不代表压缩。两侧停顿在删除中间词后会相加，分配总余量；整行删除产生相邻停顿标记时，按有效合约合并成一处，不把两处余量都留成双倍。
4. `apply_script({projectId, timelineMd:完整修改稿, preview:true})` 验证后，已获授权就同参数去掉 preview 提交。只要求预览的任务不提交。验证失败修当前稿；stale stamp 时重读并重合修改意图，不覆盖新的版本标识。
5. 提交后回读当前 Script 再开始下轮；不要继续用清理前的 Script 操作。长时间工具调用保留执行句柄，等待结果，超时先查实际状态再考虑重试。

## 机械清理的使用范围

立即应用已获授权时，可先 `clean_script({projectId, only:"fillers", track:已核实轨道})` 处理固定“呃／额”。它立即写时间线，没有 preview；用户要求先看整个改动预览时不用它，直接在 Script 中暂存全部候选。

不要无参数调用全轨清理：它可能同时统一压缩正常停顿。`longSilence` 与显式 `silence` 规则的优先级、目标长度以当前 schema 为准；需严格保留不同句间余量时，用局部 Script 压缩，而非假设批处理会理解语义。

本次经验：机械去口癖可能连带删掉左右停顿；`restore:300` 一类调用虽报告扩展，也未必恢复已完全消失的停顿。必须对照清理前源位置和回读源范围；在最新 Script 中恢复对应原有静音，继续删除犹豫音。不要仅凭报告数字声称恢复成功，也不要把旧 stamp 直接粘回来。

## 平滑与时间线证据

剪辑后 `preview_timeline(views:["timeline"], limit:100)` 按 `nextOffset` 顺序取齐所有页。不能只检查首页就说全片连续。记录 fps、准确帧范围、sourceRange 和资产身份。

优先按 `talking-head-guide` 使用 `smooth_audio`，先 `validateOnly:true` 查看实际交叉渐变与 source handles；短剪口若把被删语音重新混进来，改用 `edit_item` 在已保留片段两侧短淡化。此时避免另叠长交叉渐变。8毫秒是本次适用的起点，不是所有录音的固定最优值。`inspect_item` 回读代表性与高风险剪口的 fade、rate、gain，结构再次变化后更新平滑。

某些帧末尾会比预期多留或少留数毫秒，回读真实范围并记录。很短不等于无害：若波形或转录显示完整字词受影响，应修剪而非只标“帧对齐”。

同一 ChatCut 会话的请求可能串行锁定。分页、修改和依赖结果的调用串行执行；遇到“请求仍在运行”先等待，不能扇出几十个重试。`inspect_asset` 摘录按当前范围数量、时间与输出限制分批，保存成功批次，只补失败批次；切片边缘引文会不完整，结合完整句复核。

## 导出与失败边界

完成核对后依官方 `export` 调用 `submit_export({projectId, timelineId:最终版, format:"audio", codec:"mp3", name:本次输出名})`，记录 renderId，用 `track_export` 按返回的 checkBackAfterSeconds 检查。浏览器导出时保持对应编辑器打开；格式、码率、采样率以实际成品探测为准，不能把本地曾用的参数当成插件默认。

完成状态和 downloadUrl 才是导出结果；下载交接遵循当前宿主的正式方式，验证最终文件能访问。导出失败时按失败类别修复就绪状态或正式导出流程。安全审查拒绝、上传拒绝、blob 导航限制不能通过隐藏接口、脚本取浏览器对象或换路径绕过。

若正常导出确实不可用且本次音频交付授权允许本地渲染，可采用更安全的音频路径；依据最终回读时间线的源范围、rate、gain、淡化和转场精确生成，不能仅按文字剪辑计划重做。不能精确复现原生效果时就不声称等效，交付可编辑工程并说明文件导出缺项。此分支不适用于权限拒绝，也不把纯音频替代路径外推成可本地扁平化视频的授权。

导出后验证实际时长、完整解码、保留语句与接缝。工程成功不等于音频文件已交付；文件成功也不等于已整期听审。
