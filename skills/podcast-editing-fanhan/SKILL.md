# 播客剪辑@泛函

完整播客默认交付飞书文档：**剪辑后的音频作为文件附件放在正文最上面，随后写标题、音频说明和本期 shownotes**；同时保留可试听的音频、可继续修改的 ChatCut 工程和逐处核对记录。以自然对话为目标，保持内容逻辑、先后顺序、前后原话和说话人的情绪。已有明确剪辑与交付授权就执行到底，不增加逐阶段批准；用户只要求音频、Markdown、方案、预览或审阅时遵守该范围。飞书交付沿用本次明确授权或覆盖该对象与动作的有效长期授权，不扩张为公开分享或节目发布。

这是 [`泛函内容风格`](../../SKILL.md) 的录音编辑分支。独立调用时也先按父 Skill 的仓库同步约定核对版本；更新方法只发布到父仓 `Ivor-NCUT/fanhan-content-style`。不用全文写作语料或 Humanizer 重写实际说话内容。

## ChatCut 入口

需要剪辑或恢复时间线时，先读取当前安装的 `chatcut-desktop:chatcut-plugin-basics`，按其要求区分 hosted `mcp__chatcut__*` 与 Desktop 服务。依本次分支加载 `asset-import`、`transcription`、`talking-head-guide`、`verification`、`export`，不加载配乐或动画等无关分支。调用流程与实际踩坑见 [ChatCut 调用约定](references/chatcut.md)，首次执行和工具失败恢复时读取。已有剪辑音频且只需生成 shownotes 或交付文档时，直接进入下方文字与交付分支，不重新剪辑。

工具名和参数以当前 MCP schema 为准。本 Skill 不安装插件、不存凭据、不通过隐藏接口改数据库。项目、素材、轨道及片段 ID 从实时工具结果获取；用户切换项目或手工编辑后先回读。已有授权持续有效；上传、登录或导出遇到真实权限拒绝，停止被拒动作，不借替代路径绕过。

## 剪辑决策

- **开录前对话**：识别正式开场，剪掉调设备、试音、讨论怎么开始等准备内容；保留正式介绍及必要开场上下文。结束后的收工闲聊同理。
- **明确废段**：说“这段剪掉”是定位线索，结合上下文确认所指范围；剪去相关废段与制作指令，不能只删这四个字，也不能把它当作对其他内容的授权。
- **重复与逻辑冗余**：只删失败重说、已经完整覆盖的重复和不贡献信息的片段。留一份完整自然表达及必要引子、主体、否定、限定和因果词；不拼接不同重录里的半句话，不把第二遍新增的信息一起删掉。边界不确定就保留或缩小剪口。
- **口癖**：“呃／额”可作为固定犹豫音候选；“哎呀、就是、那个、然后、嗯、啊”依语义判断。处理“就是就是、我我、你你”等卡顿时保留一份完整起句。有强调、幽默、感叹、回应、思考或逻辑作用的表达保留；不全局替换词表。
- **停顿**：先压缩明显拖沓的长间隔。播客中约0.8秒以上是检查候选，不是自动删除阈值；一般句间可留约0.5秒，较慢转场约0.6秒，局部重说附近约0.25–0.3秒。这些是起点，按实际听感与用户要求调整。正常短呼吸、笑声、轮流说话的余量和强调停顿保留，不能统一压到零或通过变速赶时长。
- **剪口周围**：只修改已选范围及最短必要过渡，不改相邻实词、不重排观点、不加 AI 补声、配乐、全轨音量或降噪，除非本次明确要求。波形的低能量区只能帮助定位；低声语音不能当静音剪掉。

## 从录音到审阅版

1. 核验素材与音轨，确认本次目标是完整音频播客。保存原文件；在 ChatCut 保留原始时间线，复制为工作版本。已有上一版时从其复制，避免覆盖用户正在核对的版本。需要分离视频音轨时优先使用插件当前原生路径，并检查其他轨道是否重复播放同一声音。
2. 等待转录就绪后读取显示停顿的 Script，结合原音轨、词级时间和波形理解整期结构，定位正式开场、制作指令、重录和冗余。转录是证据线索，误识不能当成说话人实际改口。
3. 先完成保守内容剪辑，再做口癖与停顿精修。阶段是内部可回滚边界，清楚且已授权的任务可同一轮完成。固定犹豫音机械清理可在精修阶段先运行，随后必须重读；依赖语义的词和重复用 Script 表达。
4. **自动去犹豫音后检查其左右停顿。** 它可能连带删去全部呼吸余量，留下“词句粘连”。对照原始 Script／源时间范围，在相同位置补回少量原有停顿，通常约0.3秒；不加人工静音、不恢复犹豫音。恢复调用的计数不代表实际补回，必须检查源范围与时间线时长。
5. 用最新 Script 的原文及标识写删除和停顿压缩，先预检再提交；预检通过且已授权应用就直接提交。回读完整保留文字，核对原顺序、逻辑连接和预期保留范围；边界残留半字或误删完整词时修正，不能靠淡化掩盖语义错误。
6. 剪口最终确定后施加短淡化或插件原生平滑，回读实际参数。短词剪口应避免长交叉渐变把已删犹豫音混回来；有类似本次听感需求时，两侧各约8毫秒淡出／淡入可作起点，按剪口长度、波形和试听调整。再次改结构后重做受影响接缝检查。
7. 生成逐处记录与对比试听页，检查文件能播放、记录能定位到原版和新版。按插件原生音频导出路径取得完成的文件，验证实际导出内容和时长；排队成功不能算完成。
8. 音频版本确定后，按下方流程生成 shownotes 并完成已授权的飞书交付。再次恢复或修改剪口时，重算受影响的时间轴，使文档中的音频、说明和时间戳对应同一版。

## Shownotes 与飞书交付

生成 shownotes 或交付文档前，读取 [Shownotes 生成与交付](references/shownotes-and-delivery.md)。文字以最终保留内容为依据；主标题、PART 分节标题和时间轴条目标题都参考父 Skill 的标题要求与示例，不改写录音原话。

用户给了上期示例时，保留仍适用的节目介绍、主播介绍、联系与入群入口、小广告等固定部分，更新本期简介、嘉宾与时间轴；联系方式、数字和二维码有效期按本次事实核验。图片先下载到本地，再上传为文档图片，不引用旧飞书文档图床；Markdown 中嵌入可访问的本地图片。

**飞书正文第一项必须是真实的剪辑音频文件附件**，标题与说明写清节目、集数、版本和时长，完整 shownotes 放在下面。本地路径、普通下载链接、空附件块或上传排队不能代替已插入文件。回读核对附件名称、大小与位置、shownotes 全文及图片，再在右侧内置浏览器打开最终文档并返回链接。必要权限失败时交付已完成部分并说明缺项，不重复创建文档。

## 记录、验收与恢复

在生成记录、交付或处理用户反馈前，读取 [核对与恢复](references/review-and-recovery.md)。每个实际删除都记录原音轨范围、原话、理由、保留停顿和过渡处理。原版编号稳定；新一轮用新编号，回读帧边界差异也记入记录，不能用工具操作计数代替完整删除清单。

可使用 [时间线审计脚本](scripts/audit_timeline.py) 对比两版 `preview_timeline` 的完整结构：它核验单源单轨连续、原速与顺序，生成新增删除／多保留范围及新旧试听位置。使用限制和命令见核对参考；它不判断语义和听感。最小回归见 [测试场景](tests/scenarios.md) 与 [脚本测试](tests/test_audit_timeline.py)。

完成信号：本次范围内音频可访问、工程可继续编辑、所有调整可核对；完整交付还须 shownotes 对应最终音频、飞书附件位于正文最上面、全文与图片回读通过、文档链接可访问。说明实际完成的是文字核验、数值检查、抽听或整期听审，不把其中一种等同其他。用户指出“恢复某编号”时继续同一工程创建修订版，恢复相同源范围并更新接缝、记录及受影响的 shownotes。
