# 内容类型路由

先看这次要交付什么。口播视频初剪、静态双语字幕、顶部标题与三项交付进入 [`泛函口播剪辑`](../skills/fanhan-talking-head-edit/SKILL.md)；不加载写作语料或 Humanizer，不制作字幕动画和音效。

制作音频播客、从视频分离音频、恢复剪口，或生成 shownotes 与飞书交付文档，进入 [`播客剪辑@泛函`](../skills/podcast-editing-fanhan/SKILL.md)，由该分支主持完整交付；已有音频不重新剪辑。纯音频剪辑无需通读写作语料，也不应用 Humanizer 改写。该分支生成简介、主标题、分节标题和 shownotes 时，只有文字部分进入下面的写作路由；保真导入已有完整稿不再重写全文。

文字创作再看读者是谁，选择主类型。所有 11 篇飞书原文仍需通读；路由决定重点对照哪几篇及采用什么结构。用户当次给出的定稿或修订稿优先于旧样本。类型混合时只选一个主结构，其他原文提供语气和素材，不硬拼模板。

## 岗位 JD 子路由

- **替客户招新业务负责人、对外发布短帖**：优先看用户定稿。每个岗位单独成帖，以“招募一位 {岗位名称}”开头，不用“最近在招”起笔；接着交代已确认的岗位、地点和办公方式，把公司背景连到岗位为什么现在存在，再写方向空间、候选人实际要做的事、团队工作方式与适合谁。可以用单独一行引出重点和适量空行让读者停一下。候选人行动入口放在末尾；邮箱、薪资等只取本次材料。
- **给自己团队招人、信息较完整的长 JD**：重点看用户运营实习生与 AI Native 设计师两篇。明确付费与合作边界，再按信息量写具体收益、工作内容、期待、顾虑或加分项。不要为了模仿短帖而删掉原稿真实条款，也不要把两篇旧 JD 的承诺移给新岗位。
- **润色用户现稿**：先列出事实和限定，再调整语序、段落和语气。用户改过的词、换行和口语只在影响准确性或可读性时动；不把已确认定稿自动“规范化”。

招聘短帖硬性避免“不是 X，而是 Y”式的空泛对比。默认删掉“不是 X”，直接从“而是 Y”所表达的职责、阶段结果或判断写起；只有 X 确实构成需要澄清的误解或边界时才保留。作者旧稿里的句式是参考，不是必须复用的模板；本轮明确反馈优先。

用户定稿相对前稿的可复用改动：用直接、口语化的招募标题开场；岗位地点与现场办公紧跟开头；从真正吸引候选人的机会点带出产品空间；用自然段与冒号安排阅读停顿；把 0→1 冷启动增长能力写得更具体；以明确投递方式收束。这是岗位短帖的参照，不是所有 JD 必须逐句照抄的格式。用户后续明确要求的“招募一位 {岗位名称}”开头优先于旧样稿的具体措辞。

## X 转述帖 / 行业事件转述

在 X 上转述行业事件或新闻时，先读 [`T3 Code · Grok Bot（用户定稿）`](../examples/X转述帖/T3Code-GrokBot-用户定稿.md)。主体是把发生了什么讲清楚，具体上下文从原帖取；自己的看法只占一小段。定稿的措辞是参照，不必逐句复用。

按定稿的顺序组织：

- 用口语化的第一反应开场。定稿是「卧槽，这个流程也太丝滑了吧！」。
- 用一句话说明产品或公司是什么。
- 用短段落按时间讲事件。关键原话单独成行，保留原句里承担动作的 @。定稿把 Theo 的英文回复译成中文后拆开，并保留 @bot；回复行首自动带上的对话对象 @ 没有写进引语。
- 用一段话说清这件事值得注意的地方。
- 用一小段对照这件事以前怎么运转。定稿写的是反馈要经过市场、运营、产研，再开会、排期、对齐上下文。
- 给读者一句可以带走的判断。
- 轻轻接到作者自己的用法。定稿写的是情报和选题从 X 上监测，以及把各个 agent 上的活迁过来、把 X 当成接下来最核心的运营平台。
- 相关大账号可以单独一行 @。定稿是「马斯克牛逼！@elonmusk」，后面那句自己的安排仍属于同一处自身衔接。

相对草稿，定稿做了这些可复用的改动：把用户抱怨里过细的技术点收成白话（「用户吐槽了产品的一个小缺点，也没想着能怎么被解决」）；把引用的回复单独成行；自身衔接写成这个工具在自己工作里做什么，这篇是情报和选题从 X 上监测。

## 长文与课程增量校准

写作、重写或诊断长文与课程时，读取 [长文与课程写作](长文与课程写作.md)，并遵循 [Skill 的通用要求](../SKILL.md#长文与课程的通用要求)。用户终审样稿与最新明确修订优先于旧课程参照。先分清认知地图、观点讲解与实操教学；诊断沿核心判断、叙事推进、作者声音、案例增量与阶段负担定位，结构失效时在用户允许的重写范围内重组，不能只润色句子。纯诊断交付发现，纯润色保留原观点与范围。
